这些是性能/体验类断言，代码里没有可核对的东西，**建议改成不带具体数字的表述**，否则同样是风险点。

## 五、可直接替换的文案（供参考）

**A1 + A2（p118 填表入口）** 原文：

> 三项齐备后点「开始填表」走 /api/templates/{tid}/fill——后端立即返回 task_id（通常 200 ms 内），真正的填表计算放到 APScheduler 队列异步跑，用户可在任务中心轮询进度。

建议改为：

> 三项齐备后点「开始填表」走 /api/templates/{tid}/fill。后端在请求内同步完成字段识别、数据源筛选与写入，并设 300 秒超时保护；完成后写入 task_info（状态、耗时、准确率、输出文件），返回 task_id 供任务中心展示与按 ID 下载。

**A3（p114 文档管理）** 原文「解析任务被放到后台 APScheduler 队列异步执行」→ 改为「解析任务通过 FastAPI BackgroundTasks 在响应返回后异步执行」。

**A6 + A7（p119 置信度）** 建议整段重写为：

> 置信度由 5 个维度加权得出（`_calc_confidence`）：
> - 列名匹配度 0.25（精确 1.0 / 包含 0.9 / 模糊 0.75 / 未映射 0.55）
> - 数据源匹配分 0.25
> - 数据类型一致性 0.20（列名含数/量/GDP/人口等 → 校验数值占比）
> - 非空率 0.15
> - 同列格式一致性 0.10
> - 值合理性 0.05（长度变异系数）
>
> LLM 提取模式另用一套权重（0.20/0.20/0.20/0.25/0.15），并叠加多批采样一致性惩罚。
> 前端按 0.8 / 0.6 两档染色：≥0.8 高可信、0.6–0.8 建议复核、<0.6 建议人工修改。

**A13（p121 填表历史）** 原文「每条历史都带有「重新下载」和「再填一次」」→ 改为「每条历史支持按任务 ID 重新下载」。

**A15（p124 图片填充案例）** 山东空气质量模板没有图片列。建议改用真实存在的图片场景，或把这段从该用例下移出，改为「image_filler 能力说明」，不绑定具体用例。
