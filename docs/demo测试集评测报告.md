## 二、用例 A：山东省环境空气质量

- 模板：`2025山东省环境空气质量监测数据信息-模板.docx`（3 个表，各 8 列）
- 数据源：`山东省环境空气质量监测数据信息202512171921_0.xlsx`（20,000 行 × 18 列）
- 用户要求：3 个表分别填 `2025-11-25 09:00:00.0` 时刻的德州、潍坊、临沂

### 结果

| 表 | 源数据站点数 | 输出数据行 | 一致 |
|---|---|---|---|
| 表一 德州市 | 25 | 25 | ✅ |
| 表二 潍坊市 | 29 | 29 | ✅ |
| 表三 临沂市 | 25 | 25 | ✅ |
| 合计 | 79 | 79 | ✅ |

模板原表预留 24/28/25 行，实际数据 25/29/25，**系统自动扩行补齐，没有截断、没有留空**。

### 准确率

按「城市 + 站点名称」为主键匹配源记录，逐格比对 `区 / 空气质量指数 / PM10 / PM2.5 / 首要污染物 / 污染类型` 6 列：

```
79 行 × 6 列 = 474 格，全部一致 → 100.00%
不一致 0 条
```

空值处理正确：源中 `—` 与输出 `—` 视为等价；带标记的值（如 `4985(PF)`）原样保留。

### 耗时

解析 5.55s（1.74MB / 20,000 行）· 填报 11.51s（接口内部计时 11.03s）

## 三、用例 B：2025 年中国城市经济百强

- 模板：`2025年中国城市经济百强全景报告-模板.xlsx`（5 列，仅表头）
- 数据源：`2025年中国城市经济百强全景报告.docx`（115 段**叙事文本**，无表格）
- 用户要求：「帮我智能填表」

这条路径强制走 LLM 从自然语言里抽 100 个城市 × 4 个指标，是本测试集里最难的一例。

### 3.1 覆盖

- 原文含 GDP 叙述的段落 102 段，其中 100 段是城市数据、2 段是导语/总结
- 输出 100 个城市行，**100/100 城市段落全部覆盖，无漏城、无重复**
- 原文导语/总结段未被误当城市行

### 3.2 准确率

对 100 个城市，检查 4 个数值（GDP / 常住人口 / 人均 GDP / 一般公共预算收入）是否**同时出现在该城市自己的段落内**（排除跨行错配）：

```
4 值均在同段落命中：100/100 城市 = 100%
段落定位失败：0
```

再人工逐字核对 10 个城市（上海、北京、深圳、重庆、广州、苏州、杭州、成都、武汉、南京），全部一致。例：

| 城市 | 输出 | 原文 |
|---|---|---|
| 上海 | 56708.71 / 2487.45 / 228020 / 8500.91 | 56,708.71 亿元、2,487.45 万、228,020 元、8,500.91 亿元 ✅ |
| 苏州 | 27695.1 / 1295.8 / 213860 / 2490.23 | 27,695.10 亿元、1,295.80 万、213,860 元、2,490.23 亿元 ✅ |

### 3.3 缺陷 1（严重，已修复 §7.1）：3 行外部数据污染

输出 103 行，其中混入 3 行（第 98、103、104 行）：

```
行98   临江  3482.65  268.4  None  None
行103  云溪  2057.18  156.7  None  None
行104  青川  1486.92   98.3  None  None
```

这三个城市**不存在于百强报告原文**，它们来自 `samples/` 样例包的合成数据（`2025年临江市国民经济和社会发展统计公报（节选）.docx`），此前测试时上传过。

**根因**：`backend/routers/templates.py:1717 _fill_table_with_llm_fallback()` 里用
`vs_search(query, 320, user_id=user.id)` 从**向量库全库**检索片段，**完全忽略本次勾选的 `source_file_ids`**。
只要库里存着别的文档，LLM 就会把它们的内容当成数据源。

影响：多用户/多次上传后，填表结果会混入无关文档的数据。这是数据隔离问题，不是偶发。

## 四、用例 C：COVID-19 数据集

- 模板：`COVID-19 模板.xlsx`（6 列：国家/地区、大洲、人均GDP、人口、每日检测数、病例数，**无日期列**）
- 数据源：`COVID-19全球数据集（节选）.xlsx`（38,472 行 × 15 列）+ `中国COVID-19新冠疫情情况.docx`（31 段叙事）
- 用户要求：把两个文件中日期 `2020/7/1–2020/8/31` 的数据填入模板

### 4.1 输出构成

初测：

```
2508 行 = 40 国 × 62 天（2480 行）+ 28 个中国省级行
源区间内：41 国 × 62 天 = 2542 行
```

修复 §7.2 后：**2570 行 = 41 国 × 62 天（2542 行）+ 28 个中国省级行**，与源区间行数一致。

### 4.2 准确率（三项独立核验）

> 以下为修复后（输出 2570 行）的复算结果，可用 `scripts/demo_testset_score.py` 直接复现。

| 核验项 | 结果 |
|---|---|
| 国家固定字段（大洲 / 人均GDP / 人口）逐格 | **7626/7626 = 100%**（41 国 × 62 天 × 3 字段） |
| 每日检测数 + 病例数组合能否在该国源数据中定位 | **2542/2542 = 100%**（无编造） |
| 中国省级行关键值与 docx 段落匹配 | **112/112 = 100%**（28 行 × 4 字段） |

「输出行序与源日期顺序是否逐行对应」未纳入自动评分：模板没有日期列，行序与日期的对应关系无法从输出文件反推，只能人工抽查。

日期筛选正确：规则解析 `2020/7/1–2020/8/31` 与 LLM 解析 `2020-07-01–2020-08-31` 一致，筛出 2542 行，没有越界。

### 4.3 缺陷 2（严重，已修复 §7.2）：一个国家 62 行数据被整段误删

`Dominican Republic` 在区间内的 62 行数据全部丢失。

**根因**：`_is_summary_row()` 用子串匹配判断合计行，关键词表里有 `min`：

```python
_SUMMARY_KEYWORDS = {..., "min", "minimum", ...}
for kw in _SUMMARY_KEYWORDS:
    if kw in normalized: return True
```

`"dominican republic"` 含子串 `"min"` → 整个国家被判定为合计行 → 62 行全删。

同理会被误删的名字还有：`Dominica`、`Timor-Leste`（含 min 的变体）、任何含 `max`/`avg`/`sum` 子串的实体名。
这是**关键词未做单词边界判断**导致的误杀，属于确定性 bug。

### 4.4 缺陷 3：粒度错误，表格实际不可用

模板没有日期列，系统却把「国家 × 62 天」原样堆进去，同一国家连续重复 62 行：

```
Ireland  Europe  78661  4813608  4551  25477
Ireland  Europe  78661  4813608  3792  25489
Ireland  Europe  78661  4813608  8049  25498   ← 数据都对，但看不出是哪天
```

数据本身逐行与源一致（见 4.2），但**用户拿到的表无法区分日期**，同一国家的 62 行在业务上无法使用。
合理做法应是按国家聚合（取区间末值/求和/均值）或保留日期列。

### 4.5 缺陷 4：单位混排（已实现表头单位归一化，本模板表头缺单位）

- 英文国家行：纯数字（`4551`、`25477`）
- 中国省级行：带单位字符串（`7.3万元`、`5775万`、`12.6万份`）

同一列两种格式，无法直接排序或计算。

**已修复（2026-11-04）**：新增 `services/unit_normalize.py`，写入单元格前按**表头声明的单位**换算：

| 表头 | 源值 | 写入 | 说明 |
|---|---|---|---|
| `人均GDP（万元）` | `7.3万元` | `7.3` | 同量词，数量级一致，直接取值 |
| `人均GDP（元）` | `7.3万元` | `73000` | 万→基本单位 |
| `人均GDP（亿元）` | `7.3万元` | `0.00073` | 万→亿 |
| `人口（万人）` | `1.26亿` | `12600` | 亿→万 |
| `每日检测数（万份）` | `12.6万份` | `12.6` | 同量词 |
| `人均GDP（美元）` | `7.3万元` | `7.3万元`（原样） | 量词不同不换算，告警 |
| `人均GDP`（无单位） | `7.3万元` | `7.3万元`（原样） | 表头无单位，不猜口径，告警 |

**本用例 C 的模板表头是 `国家/地区 | 大洲 | 人均GDP | 人口 | 每日检测数 | 病例数`，
6 列全部没有单位标注**，所以系统按规则保留原样并打告警，混排现象在 C 用例中仍然存在。
要让这一列变成纯数值，需要在模板表头补上单位，例如 `人均GDP（美元）`、`人口（人）`、
`每日检测数（次）`——补完后系统会自动换算，无需改代码。

### 4.6 耗时

解析 5.55s（含 1.06MB / 38,472 行 xlsx + docx）· 填报 10.64s（接口内部 10.12s）

## 七、修复记录（2026-11-04 02:33 回归验证）

### 7.1 缺陷 1：检索限定在勾选的数据源

**改动**

- `services/vector_store.py`：`search()` 与 `_tfidf_search()` 新增 `file_ids` 参数，
  在候选池阶段就按文件过滤（不是检索后过滤，避免目标文档被无关高分片段挤掉）。
- `routers/templates.py::_fill_table_with_llm_fallback`：两路检索都带上
  `file_ids={本次 file_list 的 id 集合}`；集合为空时直接抛错。
- `routers/templates.py::_fill_table_mode`：`file_list` 为空时由「仅告警」改为
  `raise ValueError("未找到可用数据源…")`，不再静默走进 LLM 兜底。

**回归**：B 用例输出 103 → **100 行**，临江/云溪/青川 3 行消失，100 城仍全部覆盖。

### 7.2 缺陷 2：合计行改按整词匹配

**改动**：`_SUMMARY_KEYWORDS` 拆成中文组与 ASCII 组。中文仍用子串匹配；
ASCII 关键词改用正则 `(?<![a-z])(?:sum|total|min|max|…)(?![a-z])`，要求整词。

**单元验证**

```
Dominican Republic -> False   合计 -> True     Total -> True
Dominica           -> False   总计 -> True     total row -> True
Timor-Leste        -> False   平均值 -> True    SUM -> True
```

**回归**：C 用例输出 2508 → **2570 行**，`Dominican Republic` 62 行全部回来，
源区间 41 国全部在列，行序 2542/2542 一致。

### 7.3 缺陷 5：解析空结果标 error

**改动**：`routers/documents.py::_fast_parse` 在 `parse_document()` 返回空列表时，
置 `parse_status="error"`、`chunk_count=0`，任务摘要写
「未解析到任何内容：文件可能损坏、为空或格式不受支持」，并补上模块 `logger`。

**回归**

```
电商销售数据.xlsx          status=error  chunk=0    field=0   ← 明确失败
南京市2021~2024年…docx     status=done   chunk=180  field=981 ← 正常文件不受影响
```

### 7.4 缺陷 4：单位以表头为准

新增 `services/unit_normalize.py`，在 xlsx（单表 / 多表）和 docx 三处写值入口统一调用：

- `parse_header_unit(header)`：从表头提取单位，支持 `（万元）`、`(亿元)`、`/万人`、`（万）` 简写、
  `（亿元，现价）` 复合描述。
- `parse_value_with_unit(value)`：把 `7.3万元`、`1.26亿`、`12.6万份`、`1,234.5` 拆成数值 + 单位。
- `normalize_cell(value, header)`：按表头单位换算，返回写入值与告警。

三条规则：

1. 表头有单位、量词相同 → 换算到表头单位写纯数值；
2. 表头有单位、量词不同（人民币 vs 美元）→ **不换算**，保留原值并告警；
3. 表头无单位 → **不猜口径**，保留原值并告警，提示补表头单位。

不换算的两种情形都会走 `_warn_unit_once` 去重记录，不会逐格刷日志。

### 7.5 四项修复后的完整回归

| 用例 | 行数 | 核验结果 |
|---|---|---|
| A 山东空气质量 | 79 | 474/474 = 100.00% |
| B 城市百强 | 100 | 同段落四值齐备 100/100，污染行 0 |
| C COVID-19 | 2570 | 41 国全在，行序 2542/2542 一致，缺失国家 0 |
| samples 样例包 xlsx | 3 | 12/12 |
| samples 样例包 docx | 3 | 12/12 |

**A 用例与 samples 均未受影响**，说明单位归一化没有破坏原有的纯数字写入路径
（纯数字源值视为已是表头单位，原样写入）。

### 7.6 剩余一项：需业务定口径

**缺陷 3（无日期列时堆叠）** 两个可选方案，代码改动方向完全不同：

- 方案 A：模板补一列「日期」，按 国家 × 日期 展开（保持现状数据量，但模板要改）。
- 方案 B：按国家聚合，每国一行。此时「每日检测数」是求和、均值还是取最后一天？
  「病例数」是累计值还是当日新增？—— 口径不定，代码无法自行决定。
