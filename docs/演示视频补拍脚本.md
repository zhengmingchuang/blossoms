# 演示视频补拍脚本（补 75 秒，从 4:44 → 5:59）

> 目的：现有视频 **284.3 秒（4:44）**，官方要求 **5–8 分钟**，差 16 秒。
> 本脚本给出可直接照读的 75 秒增量，补完约 5:59，留足余量；同时把分辨率从 1920×1038 提到 1920×1080。
> 增量内容选「效果数据」，因为这是评审最想看、而原片讲得最薄的一段（AI 技术亮点占评分大头）。

---

## 一、录制设置（先改这个，再录）

| 项 | 设置 |
|---|---|
| 画布 / 输出分辨率 | **1920×1080**（OBS：设置 → 视频 → 基础与输出分辨率都填 1920×1080） |
| 帧率 | 30 fps |
| 录制区域 | 浏览器全屏（F11），不要留任务栏；窗口最大化后 OBS 用「窗口采集」并「拉伸到画布」 |
| 编码 | H.264 / MP4 |
| 音频 | 48 kHz，麦克风单独一路，录完确认无爆音 |
| 鼠标 | 打开「高亮点击」或点击时轻微放大，评委能看清点了哪 |

> 原片高度 1038 是因为录屏窗口没占满 1080。这次务必在 OBS 里确认预览是满幅 16:9。

---

## 二、插入位置

原片结构大致是：项目介绍 → 功能演示（上传 / 抽取 / 填报 / 对话）→ 效果数据 → 总结。

**插在「功能演示结束、总结之前」**，即原片的「效果数据」段开头。这一段天然承接前面的演示，不会显得突兀。

如果原片已有效果数据但只有十几秒，直接**替换并扩写**这一小段，不要前后重复。

## 三、分镜与台词（75 秒）

| 时间 | 画面 | 台词（可照读） |
|---|---|---|
| 0–8s | 切到 `ab_report/final_report.md` 渲染页，顶部标题「DeepSeek vs Claude 模板填表 A/B 实测报告」 | 「系统换用 DeepSeek 之后，我们做了一次严格的 A/B 实测。不是为了证明能跑，而是想量化它到底准不准。」 |
| 8–22s | 缓慢下滚到「一、结论」的指标表，鼠标依次划过四行 | 「测试用例是一份叙事型统计公报，100 个城市、5 个指标，共 400 个数据格。所有数值都藏在自然语言段落里，必须真正读懂句子才能抽出来。」 |
| 22–34s | 指标表放大：实体覆盖率 100%、逐格准确率 99.75%、忠实度 100% | 「结果：实体覆盖率 100%，逐格准确率 99.75%，也就是 400 格里对了 399 格。忠实度校验 100%，意味着每一个数值都能在原文里找到出处，没有一处编造。」 |
| 34–48s | 滚到「三、唯一分歧：苏州 GDP」，左右对照两行数字 | 「唯一错的那一格，反而是基准错了。苏州 GDP 原文是 27,695.10 亿，DeepSeek 抽对了，历史基准写成了 27,027.1。所以修正后，它的实际准确率是 400 格全对。」 |
| 48–60s | 回到指标表，指「耗时 5.7 秒」「0.035 元/次」 | 「一次完整填报 5.7 秒，5 批并发。按空闲时段计价，单次成本约 3 分 5 厘。同样的活人工做要几十分钟。」 |
| 60–70s | 切到技术文档 PDF 的「AI 安全与可控性」小节 | 「为了防编造，我们不止看准确率：每个抽取值都要回查原文做忠实度校验，置信度不足的格子会封顶并标成待确认，交给人复核。」 |
| 70–75s | 回到系统界面或团队 Logo | 「这就是我们想做的：不是让 AI 替人拍板，而是让它在可核验的前提下，把重复劳动接过去。」 |

> 语速按每秒 4–5 字估算，照读即可落在 75 秒左右。若你语速偏快，可把 48–60s 那段多停 3–5 秒。
