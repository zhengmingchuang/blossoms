# 演示视频分镜脚本（6:30 · 1920×1080 满屏）

> 现状：原片 **284.3 秒（4:44）**、分辨率 **1920×1038**，两项都不达标。
> 本脚本按 **6 分 30 秒** 重排，比 5 分钟下限多留 90 秒余量，避免语速波动踩线。
> 全片一条线：**痛点 → 界面 → 三段核心功能 → 两项 AI 技术亮点 → 量化效果 → 创新点**，
> 对应官方要求的三块内容（项目介绍 / 核心功能演示 / AI 技术亮点），并把前端交互提到显眼位置。

## 一、录制设置（先改这个，再录）

| 项 | 设置 | 备注 |
|---|---|---|
| 画布 / 输出分辨率 | **1920×1080** | OBS：设置 → 视频 → 基础与输出分辨率**都**填 1920×1080 |
| 帧率 | 30 fps | 60 fps 也可以，文件会大一倍 |
| 录制源 | 浏览器窗口采集 → 右键「变换 → 拉伸到画布」 | 原片 1038 高就是窗口没占满导致的 |
| 浏览器 | F11 全屏，缩放 100%，隐藏书签栏 | 缩放 110% 会让字变大但界面被裁，不要用 |
| 编码 | H.264 / MP4，CQP 20 | 1080p 30fps 下 6:30 约 200–400 MB，正常 |
| 音频 | 48 kHz，麦克风单独一路，-12 dB 左右 | 录完听一遍有无爆音、键盘声 |
| 鼠标 | 开「高亮点击」或点击放大 | 评委要看清点了哪里 |

**录前必做**：清空浏览器历史下拉、关掉微信/QQ 弹窗、把系统通知设为勿扰。
界面上不能出现 `.env`、API Key、真实客户数据。

## 三、三个必须看清的画面

评委是看画面打分的，这三处一定要停够时间、字号够大：

1. **模板原件 vs 填报结果并排**（3:25–4:15）——这是「样式保真」唯一的可视化证据。
2. **Agent 工具调用步骤实时点亮**（4:15–5:05）——对应评分里「Agent 是否具备工具调用能力」。
3. **400 格 / 99.75% → 100% / 忠实度 100% / 5.7 秒 / 0.035 元**（5:40–6:10）——量化证据。

建议给这三处加简单字幕条，字重加粗，位置固定在画面下方 1/6 处。

## 四、语速与字数控制

按普通话 **每秒 4.5 字** 估算，每段台词字数应接近 `时长 × 4.5`：

| 段落 | 时长 | 目标字数 |
|---|---|---|
| 开场 + 团队 | 20s | ≈ 90 字 |
| 痛点 | 35s | ≈ 155 字 |
| 系统总览 | 60s | ≈ 270 字 |
| 文档与抽取 | 90s | ≈ 400 字 |
| 模板填报 | 50s | ≈ 225 字 |
| 对话与 Agent | 50s | ≈ 225 字 |
| 安全 + 效果 | 65s | ≈ 290 字 |

念快了就多停 2–3 秒给画面，**不要靠加速语速挤时间**——评审听不清等于没讲。
