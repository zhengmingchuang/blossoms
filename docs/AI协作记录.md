| 项 | 说明 |

## 二、关键节点时间线

| 阶段 | 目标 | 交给 AI 的关键问题 | 产出 | 人工修正 |
|---|---|---|---|---|
| 1. 需求收敛 | 明确「填报」而非「生成」 | 如何在不破坏模板样式的前提下写值？ | 「复制模板文件 + 只写目标单元格」方案 | 否决了 AI 最初「用 python-docx 重建文档」的思路，实测会丢合并单元格 |
| 2. 解析层 | 多格式统一切块 | xlsx 表头行如何自动识别？ | 启发式表头探测 + 切块入库 | 真实台账前 3 行是标题与单位说明，需按非空率与文本长度加权判定 |
| 3. 抽取层 | 从叙述句里取数 | 如何让模型不编造？ | 「规则 + LLM 强制 JSON」并行，再融合投票 | 增加忠实度校验脚本，把每个数值回查原文 |
| 4. 映射层 | 列名语义对齐 | 模板列「地区生产总值」如何对上源表「GDP」？ | LLM 语义映射 + 词向量相似度打分 | 低分场景封顶置信度 0.65 并标「待确认」，不硬填 |
| 5. 填表链路 | 一次跑通 100 行 | 大表怎么控制时延与成本？ | 按 15000 字符分批 + 5 批并发 | 发现 `total_rows` 统计时机错误，见 4.2 |
| 6. 对话层 | 自然语言操作文档 | 如何让模型正确区分「改标题」与「改正文」？ | 系统提示词中写死 `style_target` 取值规则 | 初版模型频繁用 `target='all'`，改为在提示词里列举反例后收敛 |
| 7. 模型迁移 | 从闭源切到 DeepSeek | 流式 tool_use 的 JSON 分片怎么拼？ | 适配层同时支持 Anthropic / OpenAI 协议 | 见 4.1、4.3 |
| 8. 验证 | 用数据说话 | 怎么证明比另一套配置更好？ | A/B 逐格对比 + 忠实度校验 | 唯一分歧经人工核实为基准错误，见 `ab_report/final_report.md` |

## 三、真实 Prompt 原文

### 3.1 字段抽取（`services/llm_service.py::extract_fields`）

系统提示词：

```
信息提取助手。只返回JSON：{"字段名":"值"}。找不到则不包含。不要编造数据。
```

用户提示词（未指定字段时）：

```
从以下文本提取所有关键信息。包括但不限于：标题、主题、统计年份、地区、主要指标数值及单位、
关键占比、同比增长率、涉及的城市/区域、监测站点、数据类型等。

如果文本包含表格数据，提取列名和关键统计值。

文本：
{truncated}
```

设计意图：把「不许编造」写成两条可执行约束（只返回 JSON、找不到则不包含），
配合 `temperature=0.0` 与事后忠实度校验，形成三重防线。

### 3.2 字段映射（`services/llm_service.py::match_fields`）

```
你是表格填写助手。根据模板字段名，从提供的数据和文档片段中找到对应的值来填写。

规则：
1. 如果字段名是一个指标名（如"GDP"、"常住人口"），找到对应的数值
2. 如果字段名是一个文档/政策/标准/书籍标题，从文档中找到关于它的描述、进展、状态等信息作为值
3. 如果字段名是一个类别名，找到对应的分类数据
4. 如果文档中确实提到了该字段但没有详细内容，填写"已提及"或相关简要描述
5. 如果文档中完全没有提到该字段，设为空字符串
6. 不要编造数据，不要把字段名本身作为值返回
7. 如果用户要求或字段关系涉及加减乘除，允许基于已提取数据做四则运算得到字段值
8. 四则运算只能使用已给出的数据，除零或缺失数据时返回空字符串

只返回JSON：{"字段名":"值"}
```

迭代痕迹：第 6 条是实测补上的——初版模型在找不到值时会把字段名本身当答案返回
（`"GDP(亿元)": "GDP(亿元)"`），导致表格看起来填满了但全是脏数据。现在代码里还有第二道
过滤：`if vs and vs != k` 才写入。

### 3.3 对话系统提示词（`routers/chat.py::_build_system_prompt`，节选）

```
你是 DocFusion 智能文档助手，拥有以下能力：
1. 在用户已上传的文档中搜索内容并回答问题
2. 提取文档中的关键信息和实体数据
3. 编辑文档内容（替换/删除/追加文本）
4. 调整文档格式（字体、字号、加粗、对齐、行距、颜色等）
...

【核心】文档格式化工作流程（必须严格遵守）：
第一步：先调用 analyze_document 分析文档结构，确认标题段落数量和正文段落数量。
第二步：根据分析结果和用户需求，精准使用 format_document 的 style_target 参数。

【重要】format_document 文档格式化规则：
- 必须使用 style_target 参数精确区分段落类型，不要用 target='all'！
- 用户说「标题」时 → style_target='heading'，只会影响被识别为标题的段落
- 用户说「正文」时 → style_target='body'，只影响非标题段落
- 标题和正文格式不同时，必须分两次调用
- 绝对不要在一次调用中把标题格式应用到正文，反之亦然
```

### 3.4 用户要求解析（`services/data_filter.py`）

```
用户要求：{user_requirement}

模板列名：{tpl_cols}

可用数据源：{data_info}
```

「把 2020/7/1 到 2020/8/31 的数据填入模板，城市：德州市」这类自然语言要求，
先由规则解析出时间范围与筛选条件，解析失败的兜底才交给模型。

## 四、AI 产出被人工修正的真实案例

### 4.1 端口不一致导致前后端联调全挂

AI 生成的后端入口监听 `8000`，而前端 Vite 代理指向 `8800`。单看任一份文件都合理，
合起来跑就所有接口 404。修正：统一为 8000，并支持 `VITE_API_TARGET` 覆盖。
**教训**：跨文件的约定必须显式写进 README，不能依赖模型「记得」。

### 4.2 填报结果显示「0 行数据」

`routers/templates.py` 中 `total_rows` 在过滤、补行、伪合计清理**之前**取值，
实际写入 3 行却回显「0 行数据」，前端结果面板看起来像没填成功。
修正：改为保存前按最终 `rows_data` 统计。

### 4.3 思维链标签被切到两个数据包

流式输出时 `<think>` / `</think>` 可能被切分在两个 delta 之间，
直接做字符串匹配会漏掉半个标签导致内容泄漏到回答里。
修正：写 `_ThinkFilter` 缓存半截标签，跨包拼接后再判断。

### 4.4 删除会话后消息仍在

SQLite 默认不开启外键约束，`ON DELETE CASCADE` 形同虚设，出现「新会话继承旧消息」。
修正：连接时执行 `PRAGMA foreign_keys=ON`，并在删除会话时显式级联清理。

### 4.5 模型预设残留失效端点

设置页曾保留三个已停用的第三方预设（MiniMax、某中转站），点一下就 404。
修正：删除失效预设，只保留实测可用的 DeepSeek 与 OpenAI 兼容两种配置，另加自定义入口。
