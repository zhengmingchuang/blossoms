# DeepSeek vs Claude 模板填表 A/B 实测报告

生成时间：2026-10-30
被测模型：`deepseek-flash`（DeepSeek-V4.1-Flash-1017）
对照基准：`backend/exports` 中本项目历史产出（Claude 生成，任务 accuracy 标记 1.0）

---

## 一、结论

**DeepSeek 在本项目最核心的场景上不仅没有降低准确率，反而纠正了基准里的一个错误。**

| 指标 | 结果 | 说明 |
|---|---|---|
| 实体覆盖率 | **100.0%**（100/100） | 0 缺失、0 多余、0 重复 |
| 逐格准确率 | **99.75%**（399/400） | 唯一分歧经核实为基准错误，修正后为 **100%** |
| 列名合规率 | **100.0%** | 返回的 JSON key 与模板列名逐字一致 |
| 忠实度（防编造） | **100.0%**（400/400） | 所有数值均能在源文档原文中找到 |
| 耗时 | **5.7 秒**（5 批并发） | — |
| 用量 | 输入 8,432 / 输出 6,690 token | 空闲时段约 0.035 元/次 |

基准（Claude 历史产物）同口径忠实度为 99.75%，有 1 个数值在源文档中不存在。

---

## 二、方法

为让结论只反映模型能力差异，除模型本身外，其余变量全部固定：

1. **输入一致**：两侧均读取同一份源文档全文（来自 `doc_chunk`），**不走向量检索**，消除检索随机性。
2. **Prompt 一致**：复用 `routers/templates.py` 中 table_fill 的系统提示词原文。
3. **分批一致**：同样 15,000 字符上限、目标 4 批并行的动态切分逻辑。
4. **参数一致**：`temperature=0`、`max_tokens=16000`。
5. **DeepSeek 已关闭思考模式**（`thinking.type=disabled`），否则 `temperature` 会被忽略、
   且带 tools 的多轮请求会因未回传 `reasoning_content` 报 400。
6. **后处理一致**：仅做与模型无关的归一化（千分位、全角、单位、行政后缀）。

评估逻辑在开跑前做了自检，避免评分本身出错：

| 自检项 | 结果 |
|---|---|
| 基准 vs 自身 | 覆盖 100%、逐格 100% |
| 格式扰动（加千分位 / 城市名带"市" / 加空格） | 仍 100%，不误判 |
| 故意改错 10 格 | 97.5%，符合预期 |

用例：`2025 中国城市经济百强`，100 行 × 5 列 = 400 个数据格。
源文档为**叙事型 docx**（"上海以 56,708.71 亿元的 GDP 总量稳居全国第一…"），
必须从自然语言段落中抽取数值，而非直接读取表格——这是最考验抽取能力的形态。

## 三、唯一分歧：苏州 GDP

| 来源 | 值 |
|---|---|
| 源文档原文 | "苏州作为当之无愧的"最强地级市"，GDP 总量达 **27,695.10** 亿元" |
| DeepSeek 输出 | **27695.1** ✅ |
| Claude 历史产物 | **27027.1** ❌ |

**基准错了，DeepSeek 抽对了。** 因此 DeepSeek 在本用例的实际准确率为 **400/400 = 100%**。

这也说明一个常被忽略的问题：以历史产物当真值时，需警惕真值本身有错。本报告通过
"数值是否真实出现在源文档中"的忠实度校验交叉验证，避免了单纯依赖基准导致的误判。

---

## 四、局限

本报告只覆盖一个用例，以下场景**未验证**，不能据此外推：

1. **多轮工具调用（chat agent）**：项目有 11 个工具、最多 12 轮的 agent 循环。
   DeepSeek 的工具调用稳定性通常弱于 Claude，这是最可能出问题的地方，建议单独验证。
2. **图片理解**：`chat.py` 有用户上传图片的多模态路径。`deepseek-flash` 支持视觉，
   但 `deepseek-v4-pro` 明确不支持，换模型时不能选错。
3. **xlsx 数据源**：本项目对 xlsx 源只把「概览 + 样例行」写入 `doc_chunk`
   （实测 20,000 行的数据集仅存约 25 行样本），因此 xlsx 源无法做抽取层 A/B。
   若实际业务中 xlsx 源占比高，这个采样策略值得单独排查。
4. **docx 多表模板**（如山东空气质量模板的三个表）：未覆盖。

---

## 五、建议

1. **可以切**。核心填报场景（叙事文档 → 结构化表格）DeepSeek 表现不低于原 Claude，
   成本低一个量级，且当前原 Claude 中转站已失效，切换同时也是恢复可用性。
2. **切完优先验证 chat agent**。用真实指令跑几轮多工具任务，重点看：
   工具参数是否完整、是否重复调用、是否在 12 轮内收敛。
3. **打开前端设置页确认**。`routers/settings.py` 会优先显示数据库里的旧配置，
   若仍显示 `claude-sonnet-4-6`，需在页面上重存一次，否则点保存会把运行时配置改回旧值。
4. **保留回滚开关**。`.env` 中原配置已注释保留；回滚时须同时把
   `LLM_DISABLE_THINKING` 改为 `false`（Anthropic 官方 API 不接受 `thinking.type=disabled`）。
